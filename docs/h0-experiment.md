# H0 实验设计：生成器能力摸底

> 状态：设计就绪，**待开跑**——需要用户在实验目录放好 `.dvd.config.json`（apiKey/model/createUrl/queryUrl）与 dsh 重启加载 v2 插件。

## 目的

画一张「这个生成器现在**什么可控、什么不可控**」的边界图。它是一切后续实验的归因地基：
H1（句式效应 A/B）、H2（结构化句型对照）如果没有这张图，失败的镜头就分不清
「是写法不行还是模型档不行」——v1 的 S006 就是三变量纠缠、靠猜归因的教训。

## 铁律

1. **纯提示词**：只写场景事实描述，不出现任何拍摄手法词汇（景别/机位/运镜/打光话术）。
2. **每格同 prompt 重复 3 次**：视频生成有随机性，3 次才能区分「运气」与「能力」。
3. **变量最小**：换模型档时只换模型档；换参数时只换参数。
4. **写完判据再跑**：判定标准先定死，不事后改（下表）。

## Phase 1：基线两格（先跑，最便宜的认知）

| 格 | 场景选择理由 | 提示词（纯文本，一字不改） | 时长 | 重复 |
|---|---|---|---|---|
| **A1 最简** | 单人、静态、无道具运动——摸能力上限 | `一位穿白色校服衬衫、藏青过膝裙的十六七岁少女，站在晴天的校园梧桐树小径上，身旁停着一辆银灰色旧自行车，她微微仰头，微风吹动她的黑色马尾和红色发绳。` | 5s | 3 |
| **B1 历史翻车同源** | 推车行走= v1 四事故（比例失真/车留原地/位置漂移）发生的场景，直接测基线翻车率 | `一位穿白色校服衬衫、藏青过膝裙的十六七岁少女，推着银灰色旧自行车，沿两侧种满梧桐的林荫道慢慢向远处走。傍晚，夕阳暖光，地面上有她推车的影子。` | 5s | 3 |

**模型档**：用用户配置的默认档。按「质量优先」决策建议先上高保真档（人+物理镜头不省档），
低档当 Phase 2 的对照变量再用。

## 判定标准（写死，不事后改）

每格 3 次验收：

| 结果 | 结论 | 边界图记录 |
|---|---|---|
| 3/3 可用 | 该格「稳」 | 此配置下生成器稳定兑现 |
| 2/3 可用 | 「边缘可控」 | 需要重看失败样本找条件差异 |
| ≤1/3 可用 | 「不可控」 | 该维度标记为边界外，后面的实验不得把责任再推给提示词 |

## 验收标签（每片回填 verdict / verdictNote）

- `verdict` = `可用` / `不可用`
- `verdictNote` = 一句话原因 + 失败类别标签，类别沿用 v1 四事故归因：
  - **物理**：身体比例失调 / 接触不实（脚飘、影离）/ 道具恒存断裂（车留原地）
  - **空间**：方向反转 / 位置漂移 / 道路×动线违和（横穿马路型）
  - **内容**：漏元素 / 多元素 / 主体错
  - **风格**：与描述气质不符

## Phase 2：变量轮换（Phase 1 全部通过才能进，避免烧钱）

- 模型档对照：高保真档 vs 低档（同 prompt 同参数）
- 参数对照：时长 5s vs 10s；分辨率档位
- 场景对照：其他最简场景扩展边界图

## 操作节奏（配置就位后）

1. `shot_gen`（dry_run=true）→ 我贴请求体全文 + 目标地址给你过目；
2. 你点头 → 同参数去 dry_run 真提交（label 如 `h0-a1-r1`）；
3. `shot_task` 轮询取片 → 你看片给验收 → 我回填 verdict 字段；
4. 一格 3 次收齐 → 按判定表出结论 → 汇报边界图更新。
