# dsh-video-design 架构设计

> 状态：Design Doc（讨论定稿 v1）
> 作者：糖豆 × 7c
> 日期：2026-09-26

## 1. 北极星

**让用户用自然语言，生成专业的镜头语言，并驱动 seeddance / 小云雀产出符合其影视品味的视频。**

核心价值不是「能出片」，而是：

- 把「很燃」「很温柔」「主角登场」这类**模糊的自然语言**，编译成**结构化、可校验、可积累**的专业镜头语言。
- 带着 **mesync 理念**（认知 / 决策 / 品味 + 因果纠错），让插件**越用越懂用户的影视品味**，并**从错误中学习原因而非结果**。

---

## 2. 定位

**视频生成器**（不是翻译层、不是纯 prompt 模板）。

链路：自然语言 → 意图解析 → 记忆检索 → **transform（共同设计）** → 镜头语言 JSON → adapter → seeddance / 小云雀出片。

绝不把自然语言直接喂给生成 API；transform 是「人话」与「模型指令」之间那道可复用、可纠错的编译管线。

---

## 3. 六层处理链路

```
用户自然语言
   ▼
① 意图解析         用户想拍什么 / 什么情绪 / 什么用途
   ▼
② 记忆检索（mesync 内核）  召回知识 + 锁定一致性 + 注入品味 + 兜住历史纠错
   ▼
③ transform（共同设计）    自然语言 ↔ 标准镜头语言，选项化交互，逐层收敛
   ▼
④ adapter 适配层          标准 JSON → seeddance / 小云雀各自 prompt + 参数
   ▼
⑤ 生成                  单镜头片段（MVP）
   ▼
⑥ 纠错学习              记录错误原因（因果），反向强化 ② 的四层记忆
```

**依赖关系**：`② 记忆检索` 不是独立的一道工序，而是 `③ transform` 的输入源。transform 在迭代过程中反复调用记忆检索（每一轮收敛、每一次选项生成、每一次局部改写都要重新召回）。

---

## 4. 记忆五层（视频场景定制）

> 照搬 mesync 的「认知 / 决策 / 品味」三概念，并针对视频场景扩展为五层 + 纠错。

| 层 | 职责 | 类比 mesync |
|---|---|---|
| **wiki** | 拍摄手法 / 镜头语言知识库（景别、机位、运动、构图、光线、节奏、转场、色调） | 认知（knowledge） |
| **material** | 人物 / 场景 / 道具的一致性资产 | 长期稳定实体 |
| **tastes** | 影视品味（调性、偏好） | 品味（taste） |
| **decisions** | 创作决策记录 | 决策（decision） |
| **corrections** | 纠错学习 —— **记错误原因，不记错误本身** | 独立新增 |

### 4.1 纠错的精髓

- ❌ 错误做法：记「上次生成脸崩了」（记住结果，不可迁移）
- ✅ 正确做法：记「脸崩是因为 prompt 同时指定多人物 + 大范围机位运动，模型注意力分散」（记住因果，可迁移、可预防）

corrections 独立于 decisions，因为纠错是「反向学习信号」，决策是「正向创作记录」，生命周期不同。

## 5. 故事维度（数据模型的核心）

**视频创作以「故事（story）」为根节点**，而非平铺的记忆类型。

```
user
 └── story（唯一工作单元）
      ├── wiki / material / tastes / decisions / corrections（story 级）
      └── EP001 / EP002 / ...（剧集，按时间分段的 shots）
            ├── shots/（分镜片段）
            └── video.mp4（该集合成的成片）
```

### 5.1 关键结论

1. **material / tastes / decisions / corrections 是 story 级（全局一份）**，不重复持有在剧集下。
2. **user 级品味（跨故事的审美底色）从 story 级品味「升维」而来**，存放位置在 `~/.dvd`（用户全局，不跟项目走）。
3. **不做 project 层**，story 就是顶层工作单元。
4. **品味升维**：当某个 taste 信号在多个 story 反复出现 → 自动/归纳升维为 user 级。user 级是「底色/默认」，story 级是「在此故事上的具体化」，加载顺序为 user 底色 → story 覆盖。
5. **素材统一管理**：material 实体只存一份；剧集级的个性化（如「EP003 林小满穿红色风衣」）用 **db 中的引用 + 派生关系** 记录，不做文件复制。

## 6. 选项化（核心交互）

普通用户无法表述专业镜头需求。选项化是「用户」与「专业镜头语言」之间的翻译桥梁。

- Agent 从 wiki 穷举「同一场景的多种专业拍法」，给用户 2~4 个「感觉可理解」的选项。
- 用户「选 A 没选 B」= 一条最强、零成本的品味信号 → 回流 tastes。
- 选项需「正交差异」（不同手法流派），非同一手法的参数微调。
- 支持「部分锁定 + 局部再选项化」，逐层收敛（先定大方向，再定子维度）。

### 6.1 选项示例

```
🎬 主角登场 —— 三种拍法
A「压迫感登场」：低角度仰拍 + 环绕运镜 + 逆光剪影
B「温柔登场」：过肩跟随 + 浅景深 + 暖色侧逆光
C「酷炫登场」：45°斜角 + 甩镜转场 + 抽帧
```

## 7. 镜头手法「十轴穷举」框架

镜头手法不是平铺清单，而是正交维度的笛卡尔积。每个轴内封闭枚举，轴间组合开放。

1. 景别（Shot Size）
2. 机位角度（Camera Angle）
3. 机位运动（Camera Movement）
4. 构图（Composition）
5. 焦距与景深（Lens & DOF）
6. 光线（Lighting）
7. 色调与氛围（Color & Mood）
8. 时间与节奏（Time & Pacing）
9. 转场（Transition）
10. 运动主体关系（Subject framing）

> 每个轴 = 枚举类型 + 结构化参数（如 `movement: { type: "dolly-in", duration: "2.5s" }`），既保留「穷举可校验」，又保留专业表达力。
> 每个手法挂「情绪/感觉标签」，支撑选项化检索（燃 / 温柔 / 压抑 / 酷炫…）。

## 8. 工作区目录规范

```
video-name/                          ← 项目根（一部片 / 一个 story）
├── README.md
├── .dvd/                            ← 插件元数据（机器用，隐藏）
│   ├── db/                          ← sqlite（索引 / 检索 / 关联关系）
│   ├── skills/                      ← 技能提示词（md，零硬编码，可编辑）
│   └── rules/                       ← 规则（md，可编辑）
└── .story/                          ← 创作资产（内容本身，人可读）
    ├── wiki/                        ← 拍摄手法知识
    ├── material/                    ← 素材（人物/场景/道具，统一管理）
    ├── tastes/                      ← story 级品味
    ├── decisions/                   ← 创作决策
    ├── corrections/                 ← 纠错学习
    ├── EP001/
    │   ├── shots/                   ← 该集分镜片段
    │   └── video.mp4                ← 该集唯一成片
    └── EP002/
        ├── shots/
        └── video.mp4
```

### 8.1 设计哲学

- **`.dvd` = 机制，`.story` = 内容**，彻底分离。
  - `.dvd`：sqlite db + skills + rules，插件私密实现，用户一般不看不改。
  - `.story`：手法 / 素材 / 品味 / 决策 / 纠错，全部落成文件，可读、可改、可 diff、可 git 管理。
- 内容落文件，索引/关系落 db —— 与 mesync / ocms 一脉相承。

### 8.2 剧集命名

标准 `EP001` / `EP002` / `EP003` 格式（机器友好、可排序），显示层映射为「第一集 / 第二集」。

### 8.3 一集 = 多 shots + 合成 video.mp4

- 一集 = 一个最终成片（video.mp4），由该集多个 shots（分镜片段）合成。
- **MVP 只做单镜头生成**：AI 单次生成能力约 2~3 分钟，长片（如 1 小时）仍需剪辑软件，多镜头合成 / 连续性不在 v1 范围。

## 9. MVP 边界（v1）

**做：**
- 单镜头生成：自然语言 → 专业镜头语言 → 单片段出片
- adapter 只做一个（seeddance 或小云雀，待定）
- wiki + tastes + transform 三件套（最短链路）
- 选项化交互 + 纠错学习闭环

**暂缓（v2+）：**
- material 一致性（人物/场景锁定）
- 多镜头连贯叙事 + 合成
- user 级品味升维自动化
- 第二个 adapter
