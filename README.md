# dsh-video-design v2（分步验证最小核）

> **v2 宣言**：视频创作与代码生成本质不同——成片受主观审美支配、依赖提示词、结果不可控，迭代成本是真金白银+分钟级等待。因此 v2 的每一层能力上线前，必须先被一次真实成片实验证明。未经验证的假设（v1 的 11 域/卡片/编译环/确认卡/上游链/记忆五块）全部清仓，随 `master` 分支归档。

## 当前最小核（已交付）

两个工具，别无其他：

| 工具 | 做什么 |
|---|---|
| `shot_gen` | 把一段**纯文本提示词**原样直送用户配置的模型，发起一次真实生成（花钱）；落一条实验记录 |
| `shot_task` | 查任务进度；成功后下载成片到 `experiments/` 并回填实验记录 |

**插件零内置事实**（有测试红线钉住，`test/redline.test.ts`）：
- 零内置模型：模型 ID 完全来自用户配置或环境变量，缺了就报错列出缺项，绝不代填默认。
- 零内置地址：创建任务/查询任务的**完整 URL** 都由用户配置（`createUrl` / `queryUrl` 模板），插件不拼接任何路径。
- 零转译/零计价：提示词一字不改直达模型；费用不言不语，以后台账单为准。

## 用户配置

`.dvd.config.json`（**从会话工作区向上递归查找**；也可全部走环境变量，密钥推荐走环境变量）：

```json
{
  "apiKey": "…",
  "model": "…",
  "createUrl": "创建任务的完整 API 地址",
  "queryUrl": "查询任务的完整 API 地址（须含 {task_id} 占位符）"
}
```

环境变量通道：`SEEDANCE_API_KEY` / `SEEDANCE_MODEL` / `SEEDANCE_CREATE_URL` / `SEEDANCE_QUERY_URL`。

**查找起点 = 会话工作区，不是进程启动目录、也不是插件源码目录**：dsh 会话创建时自带不可变工作目录（用户在哪个目录开工作区，配置就放那个目录；`experiments/` 也落在那里）。插件源码放哪个仓库都不影响查找——源码目录与用户工作区彼此独立。

注意：示例地址不写在这里——把它写死在本 README 就等于插件内置了地址事实。**请把你实际开通的控制台地址填进配置**，插件会用你填的每一个字符。

## 实验工作流（H0 能力摸底）

完整的 H0 实验设计（基线两格、每格 3 次、判定标准先写死、验收失败类别）见 [docs/h0-experiment.md](docs/h0-experiment.md)。操作节奏：

1. 配好 `.dvd.config.json` → `shot_gen` 先 `dry_run=true` 看请求体与目标地址；
2. 确认无误去掉 `dry_run` 真提交（每次提交 = 一次真实计费）；
3. `shot_task` 轮询取片；
4. 你人工验收：`可用/不可用` + 一句原因，反馈给我记入实验记录；
5. **同一个场景、不同档位/不同参数格子逐个打**，得到这张生成器的能力边界图，再谈下一层。
