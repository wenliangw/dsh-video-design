# script2shot 心法 — 剧本 → 拍片计划（关键连接）

输入：`EP00N/script.md`（用户已确认的剧本）。
输出：`EP00N/plan.md`（拍片计划），确认后逐镜走 `_compile.skill.md` 收敛协议 + `generate_shot`。

剧本到镜头的连接点 = **卡片库**：beat 的情绪目标 → 手法卡情绪标签。卡片从此是词典不是画册——本心法保证每个镜头都有「叙事目的」出身，不做炫技空镜。

## 第一步：主体词固定表（跨镜一致性基线）

拆镜前先立表：剧本里的每个角色/场景/道具给一个**规范名 + 外貌短语模板**（如「阿墨：黑短发、左眉旧疤、深灰连帽衫」），收进 plan 顶部「主体词固定表」区块。

- 全片所有镜的主体描述**恒引用固定表**，转译时逐字复用——v1 做不了图片级一致性锁定，文本一致现在就能保住（第 3 镜和第 5 镜的「蒙面刺客」不许悄悄变成「黑衣剑客」）。
- 数据源：`.story/material/` 设定卡（若有）+ `.story/wiki/`（characters 等）。剧本新出的重要实体且未建档 → 先经 material 共识门控（提案→确认→落盘，见 `_material.skill.md`）再进表；轻量道具可不建卡，但短语模板照写。
- 已有实体出镜即引用档案，不重复建档、不另起描述。

## 拆镜规则（beat → shots）

- 每 beat 拆 1..N 镜；信息密度定额：一镜讲一个信息（新人物 / 新动作 / 新情绪落点），满了就切。
- **算术下限**：镜数 ≤ floor(beat 时长 ÷ 2)——单镜最短 2s 是生成器硬约束。3s 的 beat 拆不出 2 镜；塞不下就回 `_screenplay` 调 beat 时长分配，不在本层硬拆。
- 景别递进：建立镜头（交代空间）→ 中景（动作）→ 特写（情绪落点）；跳切（同景别硬切）必须有意图（节奏/惊吓）。
- 时长守恒：本 beat 各镜时长之和 = beat 预估时长。

## 每镜定轴顺序（固定，不许跳步）

1. **四要素基础卡（shot.foundation）**：时间/空间/人物/事件——先定几何再写词（规范读 `.dvd/doctrine/foundation.md`）。方向词纪律：先世界后屏幕——「沿路走」必须先知道路在画内是纵深（depth）还是横铺（lateral）；「画面左/右」只是投影描述，禁止裸屏幕方向词。道路走向×动线冲突、人物画面位缺失会被 `generate_shot` 硬拦。
2. **叙事目的**：一句话——这镜观众必须收到什么信息/情绪。
3. **情绪标签** → 检索手法卡：直接 read `.dvd/doctrine/cards/` 与 `.dvd/doctrine/presets/`，按 front-matter `emotion_tags` 匹配（同标签多卡时取正交差异的 2–4 张做候选，交给 compile 选项化）。
4. **11 域草案 + 时间窗**：size/angle/movement/composition/lighting/color/pacing/format 封闭轴从卡片 recipe 起步 + 按叙事目的微调；sound/vfx/performance 沿用 beat 的标注。beat「场景」栏的时间信息转录为各镜「时间窗」标注——同场景跨镜时间窗必须一致（剧情内时间流动才允许变化，并在 plan 注明）。
5. 草案是「出处明确的初值」，最终值走 compile 收敛协议（用户指哪改哪）。

### sound 域的诚实口径

沿用 beat 标注即可，但记住：**v1 出片无声**（doctrine 08-sound 记谱纪律）——sound 草案只记谱、不向用户承诺成片声音；对白以唇动/肢体表演在场。转译提示词绝不写「BGM 响起」这类会让人误以为成片有声的表达（口径对齐 `_seedance.skill.md`）。

## 相邻镜连贯约束（计划过检清单）

- 同场景 light/color 连续（跨镜色温不变）；除非剧情进入新时空。
- 180° 轴线不破（对话/追逐）；破线 = 明确意图（阵营翻转/时空切换）并在 plan 标注。
- 相邻景别跳档 ≤2（建立→中→特「LS→CU」可，「LS→ECU」不可无因）。
- 主体词全部来自固定表（表外描述 = 过检失败）。
- 人物画面位（`characters[].position.screen`）跨镜一致：写死的画左/画右继承自上一镜的 foundation 卡；换位必须解释世界原因（绕行/换位），禁止静默翻转。

## plan.md 形态（一屏可扫的映射表）

顶部 = 主体词固定表；正文表列：

| beat | 镜号(S00N) | 四要素卡（时间/空间/人物/事件） | 叙事目的 | 参考卡 | 11 域草案+时间窗 | 时长 |
|---|---|---|---|---|---|

- **四要素卡列**：每镜写 foundation 摘要（time.period / roadDirection+screenPath / 人物 id+画面位 / 事件序列），与 generate_shot 入参的 `shot.foundation` 同源，禁止漂移。
- **镜号 = `S00N`**，与 `EP00N/shots/S00N.json` 一一对应（机器可排序，命名规则见 `_workspace.rule.md`——后续重拍/加镜就顺号加，不重排）。
- 整体过用户确认一次（拍片计划是「这一集怎么拍」的共识），然后逐镜 compile。

## 逐镜执行与回灌（plan 是活文档）

- 逐镜走 `_compile`（确认卡）→ `generate_shot`（dry_run 先行）→ `video_task`。
- **修正回灌**：影响后续镜的用户修正（节奏/色调/景别基准）写回 plan 对应行并标注来源镜号与原因；单镜局部修正不扩散，但落 taste。plan 与执行不漂移 = 每镜开工前对齐的是最新 plan。
- **枚举兜底**：11 域草案与机器枚举的落差以 `generate_shot` 校验为准——第一镜 dry_run 报错即全表扫一遍同类值，修完再继续（草案是初值，校验是终审）。
- 每轮推进后更新 `.story/overview.md` 的 EP 进度区。

## 回流钩子

用户对拆镜密度/景别递进/叙事目的的修正 = 镜头语言口味 → `.story/tastes/`；「beat→镜头」的反复踩坑（时长爆表、轴线事故、固定表漂移）→ `.story/corrections/`。

## v1 边界（诚实）

- `generate_shot` 单镜生成 → 逐镜出片循环（v1）；多镜连贯叙事 + 合成为 v2——plan.md 的表结构已为 v2 铺路，不推倒重来。
- 参考卡只是出处的起点，成片结果仍是 model 的翻译——卡不承诺成片风格，只承诺「草稿方向经过词典检索」。
