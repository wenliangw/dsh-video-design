# novel2story 心法 — 小说 → 故事结构（事件推进提取）

小说是成熟故事：本心法**只提取、不创作**。与 `_story.skill.md`（口述情节创作补全版）只在提取工艺上不同，产物同形 `.story/story-structure.md`，之后 100% 合流。

## 推进单位 = 事件，不是字数

- 整本 txt / 单章节 / 千字段落，都按「事件」消化：分批读完（一批一章或几千字），每批只记事件——谁 + 做了什么 + 造成什么结果。心理、风景、议论不记。
- 主线事件链逐步成形（事件 A 导致事件 B 的因果线）；**主线弧闭合（开端-升级-高潮-收束都在）即截取**。小说未完本时，截取已闭合的弧。

## 提取四件

1. **事件弧**：主线事件的五段归位（对齐 `_story.skill.md` 的五段词表）。
2. **主角动机表**：欲望/缺陷/弧光，全部来自原文（原文有才写，没有进「待确认」）。
3. **关键角色功能表**：对手/镜子/盟友按功能归类，不按出场次数。
4. **支线取舍清单**：保留 / 合并进主线 / 删除，逐条列原因。

## 裁与舍（给用户确认，不替用户删）

- 忠实度共识门控：结构 = 对原文的裁剪。裁了什么、并了什么、舍了哪条支线——清单随结构一起交用户确认后才落盘。
- 小说精彩但「不可拍」的大段心理/议论**不在本层处理**（那属于每集 beat 化：旁白/意象/performance 转化见 `_screenplay.skill.md`），结构层只保留它们的骨架位（这一段的叙事功能是什么）。

## 产出

`.story/story-structure.md`：钩子 / 主角动机表 / 角色功能表 / 事件弧五段（每段标记原文出处章回，便于回查）/ 支线取舍清单 / 分集计划（按弧切分，每集一个推进单元）/ 待确认区。

## 红线

- 结构里不出现原文没有的新设定（缺口进「待确认」）。
- 分集计划只是按弧切分——每集内部的四拍与 beat 归 `_screenplay.skill.md`，本层不越界。
