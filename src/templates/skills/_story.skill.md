# story 心法 — 用户口述情节 → 完整故事结构（创作补全）

用户直接给自然语言情节（口述/梗概/片段）时走本心法。小说等成熟故事走 `_novel2story.skill.md`（只提取不创作）；两源产出同形的 `.story/story-structure.md` 后合流。

## 粒度与来源判定（先做）

- **整故事**（系列/完整长片）→ 本心法。
- **单片 / 预告**（一条 30s–2min 独立成片）→ 视为**单集特例**：`_screenplay.skill.md` 直接用四拍写剧本，不建全结构；若日后扩展成系列，再把已确认内容升格进结构。
- **单集**（「拍一集这样的…」）→ 直接 `_screenplay.skill.md`。
- **单镜头**（具体到某个画面）→ 直接 `_compile.skill.md`，不套上游管线。
- **混合来源**：用户给一段既有文本（小说段落/旧剧本）+ 口述想法时——既有文本部分按 `_novel2story` 的提取工艺消化（事件/动机只取原文，不发明），口述部分走本心法；主判据 = 用户意图（改编既有文本 vs 自己创作）。纯参考素材（世界观设定源）直接进 `.story/wiki/`，不占结构层。

## 定桩三要素（必须用户给，不问「你猜」）

1. **主角**：欲望（要什么）+ 缺陷（性格上的阻力，不是能力短板）。
2. **目标**：具体、可失败（「想红」不合格，「一周内投稿决赛」合格）。
3. **核心阻力**：对手/环境/自我，且与主角缺陷咬合。

三要素不全 → 逐项问（≤3 问）。用户答不出 = 故事没想好，如实说「还差什么」，不脑补。

## 事件弧五段（每步一句话：谁 + 为什么现在 + 造成什么）

开端（日常被打破）→ 升级（阻力递增 2–3 格，每格代价更大）→ 低点（主角做出最符合缺陷的坏选择）→ 高潮（代价与觉醒的正面碰撞）→ 收束（欲望达成/牺牲/失落，与缺陷呼应）。

**因果链闭合才成立**：任意两步之间能回答「为什么 A 必然导致 B」。

## 人物刻画

- **弧光**：缺陷 → 事件逼迫 → 改变，或拒绝改变（悲剧收束也成立）。
- **配角功能性**：对手（镜像主角缺陷）/ 镜子（对照）/ 盟友（提供代价）。不写闲人。
- **双写边界**：结构文件只存**叙事位**（欲望/缺陷/弧光/功能一句话）；外貌、关系、背景等**设定面**唯一归 `.story/wiki/characters.md`（结构首行指向 wiki）。两处字段不重复——同一内容最多两份在场。

## 校验两闸（本心法的核心）

- **合理性闸**：每个转折问「不这样行不行」——若角色按本性有同样好的替代方案，转折不成立；矛盾/漏洞登记「待确认」，与用户一起修，不自作主张定案。
- **延展性闸**：核心冲突的升级空间能否撑起规划集数？单薄 → 明确提议（深化支线/合并集数），容量由用户拍板。

## 产出（共识门控 + 成本知情 + 全景回写）

1. 起草 → 给用户确认结构（不是确认「好看」，是确认「合理、有延展性、人物成立」）。
2. 确认后落 `.story/story-structure.md`：
   - 一句话钩子；主角动机表（欲望/缺陷/弧光一目）
   - 关键角色功能表（对手/镜子/盟友）
   - 事件弧五段（每段一句话 + 因果）
   - 分集计划（EP00N：本集单元 + 结尾钩子 + 时长容量预估）
   - 待确认区（未解矛盾，顶置）
3. **总成本框**：分集计划落盘时附成本区间——每集镜头容量 × 单镜估值（用当前工作区默认参数跑一次 `generate_shot` dry_run 抽样单镜价），口径 =「预估区间，逐镜确认卡才定单价」。结构确认 = 成本知情签字。
4. **overview 回写**：一句话故事 / 卡司速览 / 进度 / 待确认区同步更新（`.story/overview.md` 是唯一全景注入入口）。
5. 人物/世界观定稿同步 `.story/wiki/`（判定见 `_sync_wiki.rule.md`）。

## 回流钩子

用户对本层产物的每次修正都是信号：口味类（钩子风格、集数偏好、拉长/砍短倾向）→ `.story/tastes/`；重复踩坑（「此类转折两次被否」）→ `.story/corrections/`（同「改这里→检查哪里」形态，分类见 `_correction.rule.md`）。

## 红线

- 不编造用户没说的人物结论；缺口进「待确认」不硬填。
- 用户没拍板的结构不落盘；落盘后再动工 `_screenplay`。
- 成本框是预算知情不是定价——不因预估高擅自砍集数；砍/合是用户的决定。
